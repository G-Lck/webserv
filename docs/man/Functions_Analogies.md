# Webserv: Core C++98 Network Functions & Analogies

To build a web server, we are the orchestrator between the OS network stack and our application. Here is the breakdown of the required POSIX C functions, using real-world analogies to make the architecture click.

| Function | What it does technically | The Real-World Analogy | Why Webserv needs it |
| :--- | :--- | :--- | :--- |
| **`socket()`** | Asks the OS for a new communication endpoint and returns a File Descriptor (fd). | **Buying a smartphone.** It has the hardware to make calls, but it doesn't have a phone number yet. | we need one listening socket for every `host:port` combination in our `.conf` file. |
| **`setsockopt()`** | Modifies the behavior of a socket. | **Carrier Settings Override.** If our phone crashes, the carrier locks the number for a minute. `SO_REUSEADDR` forces the carrier to let we use our number again immediately. | When we inevitably restart our server during testing, it prevents the "Address already in use" error. |
| **`bind()`** | Attaches a specific IP address and Port to our socket. | **Getting a SIM card.** we are assigning a public phone number (e.g., `127.0.0.1:8080`) to our device so people know what to dial. | Clients need an exact address to send their HTTP requests. |
| **`listen()`** | Marks the socket as passive, allowing it to accept incoming connection requests. | **Turning on the ringer & voicemail.** we tell the phone to start queuing up incoming calls (the `backlog`) instead of ignoring them. | Tells the OS to hold clients in a waiting line until our program is ready to ansour them. |
| **`fcntl()`** | Manipulates file descriptor flags (specifically applying `O_NONBLOCK`). | **Hiring an impatient secretary.** Instead of waiting on the line for someone to speak (blocking), the secretary asks "Anything to say?" and if the caller is silent, instantly hangs up to check other lines. | **Critical:** Ensures our single-threaded program never freezes while waiting for a slow client to send a request or receive a response. |
| **`poll()`** | Monitors an array of file descriptors to see if any are ready for I/O. | **The Switchboard Operator.** Instead of we checking 100 phones one by one, the operator puts we to sleep and only taps our shoulder when a specific phone actively has a voice on the line. | The core engine. It saves massive CPU cycles by only waking up our server when data is actually ready to be read or written. |
| **`accept()`** | Plucks the first incoming connection off the listening queue and gives we a new socket fd. | **The Receptionist Transfer.** The main number (`listen` socket) just rings. `accept()` answers and hands the caller a *dedicated, private phone line* (new socket) so the main number is free to ring for others. | Gives we the actual pipeline to talk to the specific user. we must add this new socket to our `poll()` array. |
| **`recv()` / `read()`** | Pulls raw bytes from the client's socket into our buffer. | **Taking notes from a caller.** Because they speak in chunks (non-blocking), we might only catch half a sentence. we must wait for them to speak again to finish the note. | we read the raw HTTP string. we must buffer it until we see `\r\n\r\n`. |
| **`send()` / `write()`** | Pushes raw bytes from our buffer into the client's socket. | **Reading a script to the caller.** If the script is 10 pages long, we might only read 1 page before we have to breathe. we must remember where we stopped and read page 2 later. | Sends the HTTP response. Because of non-blocking sockets, we cannot send a 5MB image in one go; we must chunk it across multiple `POLLOUT` events. |
| **`stat()`** | Asks the OS for metadata about a file path. | **Checking the filing cabinet index.** Before we grab a file, we check its index card: Does it exist? Is it a folder, or a single paper? | Used to determine if the requested URI is a 404, a static file, or a directory that needs an `autoindex`. |
| **`pipe()`** | Creates a unidirectional data channel in memory, returning two fds (read/write). | **Pneumatic tubes.** One tube sends our data down to the basement (the CGI script), the other tube brings the ansour back up to our desk. | Strictly for CGI. The server writes the POST body to one pipe, and reads the CGI HTML output from the other. |
| **`fork()`** | Clones our entire server process into a Parent and a Child. | **Cloning werself.** we stay at the front desk to ansour phones. our clone goes to the basement to process the messy CGI task. If the clone blows up the basement, we are still alive at the front desk. | Isolates CGI execution. If a PHP script crashes or loops infinitely, it kills the child process, not our main web server. |
| **`dup2()`** | Forces one fd to point to the same file as another. | **Rerouting the clone's senses.** we tape the clone's mouth to the "up" tube (`STDOUT`) and their ear to the "down" tube (`STDIN`), so they can only communicate via the tubes. | Tricks the executed CGI script into reading our pipe instead of the keyboard, and writing to our pipe instead of the terminal screen. |
| **`execve()`** | Replaces the current process with a new program. | **The Brainwash.** our clone completely forgets who they are (the Webserv C++ code) and transforms into the PHP or Python interpreter. | Actually runs the CGI executable. we pass it the HTTP headers mapped as CGI environment variables. |
| **`waitpid()`** | Waits for a child process to change state (die). | **Checking the graveyard.** we quickly peek out back to see if our clone finished their job (`WNOHANG`). If we don't do this, zombie clones pile up and shut down the building. | Cleans up CGI processes. we must use `WNOHANG` so checking for dead children doesn't freeze our `poll()` loop. |
